# UFO Catcher 시뮬레이터 — 橋渡し(하시와타시) / 2발톱

일본 클레인 게임의 **橋渡し(하시와타시 — 두 봉 사이로 떨어뜨리기)** 설정을
3D 물리로 재현. 두 평행한 봉 위에 경품이 얹혀 있고, 2발톱 클로로 경품을
밀거나 잡아 봉 사이 간격으로 떨어뜨리면 획득.
Three.js 렌더링 + Cannon-es 강체 물리.
봉 간격·봉 굵기·봉 마찰·아암 힘·발톱 마찰·경품 무게·경품 크기 등
운영자 설정값을 실시간 슬라이더로 조정해 실제 기계와 비교 검증할 수 있도록 설계됨.

## 실행

빌드 단계 없음. 정적 파일 서버만 띄우면 된다.

```bash
cd ufo-catcher
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 열기
```

또는 Node가 있으면:

```bash
npx serve -p 8000
```

> ES module + importmap 사용. `file://`로 직접 열면 CORS 차단됨.

## 조작

| 입력 | 동작 |
|---|---|
| `↑` / `W` | 클로 앞으로(-Z) |
| `↓` / `S` | 클로 뒤로(+Z) |
| `←` / `A` | 클로 왼쪽(-X) |
| `→` / `D` | 클로 오른쪽(+X) |
| `Space` | 드롭 시작 |
| 마우스 드래그 | 카메라 회전 |
| 스크롤 | 줌 |

`Space` 한 번 누르면 자동 시퀀스 진행: **하강 → 발톱 닫기 → 상승 → 구멍 위 이동 → 발톱 열림(낙하)**.
구멍에 떨어지면 `획득`, 도중에 떨어뜨리면 `실패`로 카운트.

## 우측 패널 — 운영자 설정

### 봉 (橋渡し 핵심 변수)

| 항목 | 단위 | 기본 | 의미 |
|---|---|---|---|
| **봉 사이 간격** | m | 0.060 | 두 봉 중심간 거리. 경품 한 변보다 작아야 얹힘. 클수록 잘 떨어짐. |
| **봉 굵기 (반지름)** | m | 0.008 | 봉 두께. 가늘수록 경품이 봉 위에서 균형 잃기 쉬움. |
| **봉 ↔ 경품 마찰** | — | 0.40 | 작을수록 봉에서 미끄러져 잘 빠짐 (실제 기계의 표면 처리에 해당). |

### 경품

| 항목 | 단위 | 기본 | 의미 |
|---|---|---|---|
| 경품 한 변 | m | 0.100 | 큐브 한 변 길이. 봉 간격보다 커야 얹힘. |
| 경품 무게 | kg | 0.20 | 무거울수록 봉이 휘는 효과는 없지만, 클로 슬립은 빨라짐. |
| 경품 개수 | — | 1 | 봉 위 일렬 배치. |

### 클로

| 항목 | 단위 | 기본 | 의미 |
|---|---|---|---|
| 아암 힘 | Nm | 3.0 | 힌지 모터 최대 토크. |
| 발톱 ↔ 경품 마찰 | — | 0.50 | 발톱이 잡을 때 그립 강도. |
| 리프트 속도 | m/s | 0.40 | 클로 상승·하강 속도. |
| 이동 속도 | m/s | 0.50 | X·Z 평면 이동 속도. |

### 페이아웃 (assist) 모드

실제 기계의 “N회 실패 후 강한 모드” 동작을 모사.

- `アシスト 모드 활성화`: 켜면 활성.
- `aassist 발동 회수`: 연속 실패가 이 값에 도달하면.
- `아암 힘 (assist 발동 시)`: 그 회 한해 이 힘으로 잡음. 획득 시 카운터 리셋.

이 모드의 평균 회수율을 측정하면 실제 기계의 1/N 페이아웃과 비교 가능.

## 검증 프로토콜 (실제 기계와 비교)

### 1. 봉 간격 — 안정 / 불안정 임계점

경품 한 변 = 0.10m 기준, 봉 간격을 0.05 → 0.06 → 0.07 → 0.08 → 0.09 m 로
바꿔가며 각 100회 (자동 시뮬).

| 봉 간격 / 경품 비 | 예상 거동 | 시뮬 회수율 | 실제 기계 회수율 |
|---|---|---|---|
| 0.5 (0.05 / 0.10) | 매우 안정. 거의 안 떨어짐 | … | … |
| 0.6 | 안정 | … | … |
| 0.7 | 가끔 떨어짐 | … | … |
| 0.8 | 자주 떨어짐 | … | … |
| 0.9 | 거의 매번 떨어짐 | … | … |

→ 실제 기계의 “설정” 단계와 일치하는 비율 조합을 찾는다.

### 2. 봉 마찰 캘리브레이션

봉 간격·경품 크기 고정. `barFriction`을 0.1 → 0.3 → 0.5 → 0.7 → 1.0 변경.

봉 마찰이 낮을수록 경품이 봉 위에서 미끄러지며 자세를 잃기 쉽다. 실제 기계의
봉 표면 재질(스테인리스 vs 코팅)에 해당하는 값을 찾는다.

### 3. 슬립 메커니즘 정성 검증

- 클로가 경품을 잡고 들 때, 경품이 발톱 사이를 미끄러져 봉 위로 다시 떨어지는가?
- 경품이 봉 위에서 균형 잃고 회전하며 사이로 빠지는가?
- 무거운 경품 → 클로 그립 약하면 즉시 슬립?
- 가벼운 경품 → 들리지만 봉 사이 간격이 좁으면 다시 안착?

## 물리 모델

```
Cannon-es World (gravity = -9.81 m/s²)
├── Cabinet
│   ├── 평탄한 바닥 (정적 박스)
│   ├── 벽 4면 (정적, 시각용 유리)
│   └── 봉 ×2 (정적 원통, Z축 정렬, 간격·반지름 동적)
├── Claw
│   ├── Hub: KINEMATIC body (코드로 위치 직접 제어)
│   └── Prongs (×2): DYNAMIC, mass 0.05kg each
│       └── HingeConstraint(z축) + Motor(maxForce = armForce)
└── Prize: DYNAMIC box (size = settings.prizeSize, mass = prizeMass)

ContactMaterial (런타임 가변 항목 표시):
  claw  ↔ prize : friction = settings.friction        ★
  prize ↔ bar   : friction = settings.barFriction     ★ (하시와타시 핵심)
  prize ↔ prize : friction = 0.4
  prize ↔ floor : friction = 0.6
  prize ↔ wall  : friction = 0.3
```

### Win 판정

1. RELEASING 끝 후 1.5초 SETTLE 단계 진입
2. SETTLE 끝났을 때 어떤 경품의 `body.position.y < BAR_HEIGHT - 0.05`이면
   봉 사이로 떨어진 것 → **win**
3. 아니면 봉 위 또는 캐비닛 바닥 위에 남아 있음 → **lose**

### 모델링한 것 ✓

- 발톱 모터 토크 한계 (외부 회전을 못 막을 만큼 약하면 슬립)
- 정/동 마찰 (Cannon은 단일 계수)
- 다체 접촉 (경품 더미 위에서 발톱이 다른 경품과도 접촉)
- 경품-경품 충돌 (옆 경품을 밀치면서 잡히는 거동)
- 키네매틱 hub로 인한 정확한 클로 궤적

### 모델링하지 않은 것 ✗

- 발톱의 고무 그립(소프트 접촉) — Cannon은 강체만 지원
- 봉제인형의 변형(soft body) — 박스로 근사
- 케이블 동력학(흔들림) — 시각적 라인만
- 풍속/공조 영향
- 광학(센서로 경품 통과 감지) — 단순 좌표 검사로 대체
